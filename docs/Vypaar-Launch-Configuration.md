# Vypaar Management — Isolated launch configuration

This branch is configured as a separate Vypaar product, not as a K&B Management Nexus deployment. Do not point it at the K&B Firebase project, K&B Render API, K&B Android package, or K&B OTA channel.

## Application identity

- Android application ID: `com.vypaar.management`
- App name: `Vypaar Management`
- Frontend API base: `VITE_API_BASE_URL`
- Backend Firebase project: `FIREBASE_PROJECT_ID`
- Render service name in the Blueprint: `vypaar-management-api`
- OTA publishing: disabled until a separate Vypaar release channel is intentionally configured.

## GitHub Actions secrets required before an Android APK can build

Add these as repository Actions secrets. Never put their values in source files, commits, issues, or chat.

| Secret | Purpose |
|---|---|
| `VYPAAR_API_BASE_URL` | HTTPS base URL of the separately deployed Vypaar API |
| `VYPAAR_FIREBASE_PROJECT_ID` | Firebase project ID for Vypaar |
| `VYPAAR_ANDROID_GOOGLE_SERVICES_JSON_BASE64` | Base64-encoded `google-services.json` from that same Vypaar Firebase project |

The APK workflow deliberately fails early if these secrets are absent or the Google Services file belongs to another project/package.

## Render environment variables

The Blueprint is set to the Vypaar rebuild branch and has automatic deployment disabled. Configure these variables on the new Vypaar service:

| Variable | Value |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Service-account JSON for the Vypaar Firebase project |
| `FIREBASE_PROJECT_ID` | The exact same project ID as the service account |
| `CORS_ORIGINS` | Comma-separated allowed website origins, plus `capacitor://localhost` for the Android app |
| `ADMIN_INITIAL_PASSWORD` | Strong initial administrator password |
| `ADMIN_RECOVERY_CODE` | Strong one-time/recovery secret |
| `JOB_SECRET` | Generated by Render Blueprint |

Do not reuse the K&B Firebase service account or project. The backend refuses to start when `FIREBASE_PROJECT_ID` is absent or does not match the service account.

## Firebase Hosting

The Firebase Hosting target has been changed to the separate site ID `vypaar-management`, and the old K&B default project mapping has been removed. Create that Hosting site in the Vypaar Firebase project before using the hosting deployment script. The script requires `VYPAAR_FIREBASE_PROJECT_ID`; it will not silently deploy to the K&B project.

## Business data separation

The first workspace uses the legacy top-level collections in the Vypaar database so the initial workspace works without a destructive migration. Every subsequently created workspace uses its own `businesses/{businessId}/{collection}` namespace. User accounts, sessions, the business registry, membership records, and public staff-registration tracking remain global identity/control collections. All operational collections are scoped by the authenticated session's business context. Background attendance and reminder jobs iterate each active business separately.

## Legal launch blockers

The Terms and Privacy page is linked from sign-in, but the operator name, registered address, support/privacy contacts, effective date, actual service providers, retention periods, and legal jurisdiction are placeholders. Complete them and obtain Indian legal review before public launch.
