# K&B Render backend deployment

## Active architecture

- React + Capacitor frontend is built from this repository.
- The Render Node web service runs the active API from `render-backend/`.
- Firebase Admin SDK connects the backend to Firestore project `kandb-net-sevice`.
- K&B ID/password authentication is app-managed; Firebase Authentication is not used for staff/admin sign-in.
- Firestore direct client reads/writes are denied by `firestore.rules`.
- Existing Firestore records are not cleared or migrated by deployment.
- The six-month retention screen is an admin reminder only; deletion requires explicit admin confirmation.

## Render service setup

The root `render.yaml` describes the Node web service in Singapore. It runs from `render-backend/`, exposes `/api/_healthcheck`, and has `autoDeploy: false`.

Configure these environment values directly in Render:

- `FIREBASE_SERVICE_ACCOUNT_JSON`: private service-account JSON for project `kandb-net-sevice`.
- `ADMIN_INITIAL_PASSWORD`: strong initial owner password for `Brajraj`.
- `ADMIN_RECOVERY_CODE`: separate strong recovery code.
- `JOB_SECRET`: generated by the Blueprint; protects `POST /internal/jobs/tick`.

Do not put any of these values in Git, documentation, screenshots, issues or chat.

## Scheduled jobs and free-tier limits

The default-branch workflow `.github/workflows/backend-keep-alive.yml` wakes the API and calls the protected job-tick endpoint every five minutes. Configure GitHub Actions secret `K_B_JOB_SECRET` to match Render `JOB_SECRET` exactly.

The job monitor processes automatic checkout, GPS grace reminders/cancellation, task/subscription reminders and pending push delivery when invoked. A free Render service can sleep, so scheduled timing is best-effort. Do not promise exact real-time GPS enforcement until the scheduler has been observed running successfully or a continuously available worker is configured.

The CI workflow `.github/workflows/render-backend-check.yml` runs type-checks, automated tests, route checks and live API smoke checks on pushes/PRs. It is not the scheduler and must not run every five minutes.

## Android live updates

The Render API exposes `POST /api/app-updates/check`. It reads the latest immutable OTA release from the public GitHub repository and returns a compatible Android bundle URL and SHA-256 checksum. The `.github/workflows/ota-release.yml` workflow publishes web-only bundles after changes reach `main`. The endpoint is read-only and does not require a staff session.

## Android, maps and push

The APK workflow can build the debug APK. For Android push, configure GitHub Actions secret `ANDROID_GOOGLE_SERVICES_JSON_BASE64` with the base64-encoded Firebase Android `google-services.json` for package `kandbnet.service2010`.

Staff location cards open their exact coordinates using a standard Google Maps URL. No Maps JavaScript API key or billing account is needed.

## Verification limits

Backend type-checks, automated tests, web production build and API smoke checks do not replace Firestore data-integrity tests, live role/permission tests with real accounts, physical Android background-location acceptance or push delivery tests. Complete the checklist before staff rollout.
